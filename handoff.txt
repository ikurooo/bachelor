Wasmtime/containerd setup

The important part of the project is the Wasmtime containerd shim.

We built the shim from the Runwasi GitHub repository, rather than downloading a prebuilt shim.

Repository:

https://github.com/containerd/runwasi

The intended source-build process was:

git clone https://github.com/containerd/runwasi.git
cd runwasi
make build-wasmtime
sudo make install

The resulting shim was installed as:

/usr/local/bin/containerd-shim-wasmtime-v1

Verified with:

ls -l /usr/local/bin/containerd-shim-wasmtime-v1

It existed as an executable owned by the user:

-rwxr-xr-x 1 user user 46990376 Sep 27 20:29 /usr/local/bin/containerd-shim-wasmtime-v1

We did not modify .bashrc or manually add a PATH entry for the shim.

The important thing is that the executable is installed at:

/usr/local/bin/containerd-shim-wasmtime-v1

K3s/containerd Wasmtime configuration

K3s's generated containerd configuration contained:

[plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.'wasmtime']
  runtime_type = "io.containerd.wasmtime.v1"

[plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.'wasmtime'.options]
  BinaryName = "/usr/local/bin/containerd-shim-wasmtime-v1"

Verified using:

sudo grep -i wasmtime /var/lib/rancher/k3s/agent/etc/containerd/config.toml

The configuration connects Kubernetes' RuntimeClass to the Wasmtime shim.

Conceptually:

Kubernetes Pod
      |
      | runtimeClassName: wasmtime
      v
RuntimeClass
      |
      | handler: wasmtime
      v
containerd
      |
      | io.containerd.wasmtime.v1
      v
/usr/local/bin/containerd-shim-wasmtime-v1
      |
      v
Wasmtime
      |
      v
app.wasm

WASM container image

The WASM app was packaged as:

app-wasm:latest

The image was available directly to K3s/containerd, with the Kubernetes manifest using:

image: app-wasm:latest
imagePullPolicy: Never

Docker inspection showed:

docker inspect app-wasm:latest --format '{{.Config.Entrypoint}} {{.Config.Cmd}}'

which returned:

[] []

Initially this caused:

CreateContainerError

with:

failed to generate spec: no command specified

The solution was to specify the WASM application's command/entrypoint appropriately in the Kubernetes configuration.

After fixing that, the Pod successfully ran.
Working Kubernetes Pod

The Pod is:

wasm-app

The important part of its YAML is:

spec:
  runtimeClassName: wasmtime
  containers:
    - name: app
      image: app-wasm:latest
      imagePullPolicy: Never

The Pod ultimately reached:

1/1     Running
